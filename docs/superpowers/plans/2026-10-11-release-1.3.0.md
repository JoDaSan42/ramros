# Release 1.3.0 — Four Idea Clusters in Consecutive Increments

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement the eight brainstormed ideas from 2026-10-10 as four consecutive increments (foundation → live-view interaction → diagnostics → polish), staying at version 1.2.x during development and releasing 1.3.0 at the end.

**Architecture:** Increment 1 introduces the per-workspace `ramros.json` config (new `WorkspaceConfigService`) plus external bag folders and rqt_bag in the tools tree. Increment 2 builds live-view interactivity (enable toggle persisted in `ramros.json`, topic pub, service call, runtime parameters) on top of that config and `Ros2CliService`, plus a shared read-only document provider for command output. Increment 3 adds diagnostics (interface definitions via `ros2 interface show`, `ros2 doctor`). Increment 4 polishes the package wizard and adds create buttons to the category tree view.

**Tech Stack:** TypeScript (strict), VSCode Extension API (^1.85), Jest (ts-jest, unit + integration with vscode mock), no new npm dependencies.

**Spec:** `docs/ideas/2026-10-10-bag-folders-ramros-json.md`, `docs/ideas/2026-10-10-live-view-toggle.md`, `docs/ideas/2026-10-10-topic-pub-live-view.md`, `docs/ideas/2026-10-10-service-call-live-view.md`, `docs/ideas/2026-10-10-runtime-params-live-view.md`, `docs/ideas/2026-10-10-interface-show-definition.md`, `docs/ideas/2026-10-10-ros2-doctor-health-check.md`, `docs/ideas/2026-10-10-wizard-maintainer-and-category-create-buttons.md`

## Global Constraints

- `package.json` version stays `"1.2.1"` until Task 20 sets it to `"1.3.0"`. No intermediate version bumps.
- No new npm dependencies. Only `vscode` API and Node builtins (`fs`, `path`, `child_process`, `os`).
- TypeScript strict mode; `npm run lint` and `npm run typecheck` must stay clean.
- Test commands: `npm run test:unit` (jest unit config), `npm run test:integration` (jest integration config with vscode mock). Run a single suite with `npx jest --config=jest.<unit|integration>.config.ts <path>`.
- All user-facing strings in English.
- Follow existing patterns: `TreeItemBase` subclasses with `contextValue` + `package.json` menu contributions, `Ros2CliService` singleton for CLI calls, `terminalManager.executeInNewTerminal` for interactive tools, `execAsync` with `{ encoding: 'utf-8', timeout }` for captured output.
- Commit messages follow the repo's conventional-commit style (`feat:`, `fix:`, `docs:`, `chore:`, `test:`).
- **Decisions made during planning** (resolved open questions from the idea docs):
  - External bag folders are scanned top-level only (no recursion).
  - rqt_bag is exposed as an inline icon plus a context menu entry on bag file items.
  - `ramros.json` changes on disk hot-reload via a `FileSystemWatcher`.
  - The live-view toggle is a view-title eye button plus a first-row hint item (a literal switch under the title bar is not possible in tree views).
  - `ramros.json` is resolved against the **first** ROS2 workspace (`treeProvider.getWorkspaces()[0]`).
  - Health check runs plain `ros2 doctor` (not `--report`).
  - Service-call responses are shown in a read-only document (better than an info message for multi-line output).
- **Non-goals:** service-call Phase 2 (per-field form UI), recursive bag scanning, Problems-panel surfacing of doctor warnings.

## Review Focus

1. **Corrupt or missing `ramros.json`** must never crash the extension — the config service returns `{}` and logs a warning. Test: Task 1.
2. **Unplugged/unreadable external bag folder** (USB drive removed) renders as an empty folder, no throw — `scanBagFolder` catches fs errors and returns `[]`. Test: Task 2.
3. **Single quotes inside service-call JSON** must survive shell quoting — `buildServiceCallCommand` produces a POSIX-safe command. Test: Task 7.
4. **Unbuilt interface** (`ros2 interface show` fails) shows a colcon-build hint instead of opening an empty document. Test: Task 14.
5. **Live view disabled** performs zero CLI polling — root children are exactly the disabled hint item and no interval is running. Test: Task 9.
