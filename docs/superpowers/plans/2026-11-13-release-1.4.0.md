# Increment A — Live-View Lazy Loading

**Ziel:** Refresh-Tick = genau 2 CLI-Calls (`ros2 node list`, `ros2 topic list`); Node-/Topic-Info erst beim Aufklappen (Provider-Cache, TTL bis zum nächsten Tick). System-Topic-Filter bleibt auf Zählern wirksam. Element-Fire ohne Info-Refetch-Loop.

**Design-Präzisierung ggü. Spec:** Statt Zeit-TTL gilt „Cache gültig bis zum nächsten Tick" (`newTick()` leert den Cache) — äquivalent zur Tick-TTL, timer-frei, deterministisch testbar.

- `src/core/live-info-cache.ts` — NEW: Tick-basierter Cache (pure).
- `src/treeview/live-items.ts` — MODIFY: `LiveNodeItem`/`LiveTopicItem` bauen Description aus `info?: LiveInfo | null`; `expandedChildren`-Callback-Injektion.
- `src/treeview/live-tree-provider.ts` — MODIFY: Eager-Fetch raus, Lazy-Fetch + pro-Element-Fire rein.
- `src/__tests__/unit/live-info-cache.test.ts` — NEW.
- `src/__tests__/integration/live-tree-provider.integration.test.ts` — MODIFY (Lazy-Tests).

**Interfaces (A → später):** `LiveNodeItem(name, infoLoader?)`, `LiveTopicItem(name, infoLoader?)` mit `refreshFromInfo(info: NodeInfo | TopicInfo): void`; Provider-fire über bestehendes `_onDidChangeTreeData.fire(element)`.

```typescript
export class LiveInfoCache<T> {
  private readonly entries = new Map<string, T>();

  get(name: string): T | undefined {
    return this.entries.get(name);
  }

  set(name: string, value: T): void {
    this.entries.set(name, value);
  }

  newTick(): void {
    this.entries.clear();
  }

  snapshot(): Map<string, T> {
    return new Map(this.entries);
  }

  size(): number {
    return this.entries.size;
  }
}
```

**Interfaces:**
- Consumes: `LiveInfoCache<T>` (A1); `cli.getNodeInfo(name)`, `cli.getTopicInfo(name)` (existierend).
- Produces:
  - `type LiveNodeInfo = { name: string; publishedTopics: string[]; subscribedTopics: string[]; serviceServers?: ServiceServerInfo[] }` (entspricht `NodeInfo` aus `ros2-cli-service`).
  - `LiveNodeItem` Konstruktor: `(nodeName: string, info?: LiveNodeInfo)` — gleiche Signatur wie heute (info bleibt optional, item bleibt ohne Info konstruierbar).
  - `LiveTopicItem` Konstruktor: `(topicName: string, info?: TopicInfo)` — **Änderung**: statt `messageType/publishers/subscribers` als Einzelargumente wird das ganze `TopicInfo`-Objekt übergeben (Call-Sites nur im Provider).
  - `LiveTreeProvider` neue public Methoden: `async ensureNodeExpanded(item: LiveNodeItem): Promise<void>` und `async ensureTopicExpanded(item: LiveTopicItem): Promise<void>` — laden Info aus CLI (falls nicht im Cache), setzen sie aufs Item, feuern pro Element.
  - `LiveTreeProvider.getNodeInfo(name)` / `getTopicInfo(name)` bleiben public (existierende Tests + extension.ts-Nutzung via CLI-Path unverändert).

**Verhalten (Spec-Auszug, verbindlich):**
- Folder-`getChildren` konstruiert Items nur mit Name (kein `getNodeInfo`/`getTopicInfo`-Call).
- Description vor Fetch: `running` (Node) bzw. `''` (Topic) — wie heute, wenn info fehlt.
- Beim Aufklappen: `getChildren()` des Items delegiert an den Provider-Loader (Injektion), der Info fetched, cached und per Element feuert; danach normale Children + aktualisierte Description.
- Cache-TTL: Provider ruft `cache.newTick()` beim Tick-Fire (in `startAutoRefresh`-Callback und `refresh()`), **bevor** das tree-Event feuert.

- [ ] **Step 3: Implement**

`live-tree-provider.ts`:
- Feld: `private readonly infoCache = new LiveInfoCache<NodeInfo | TopicInfo>()` — zwei Instanzen (`nodeInfoCache`, `topicInfoCache`) für Klarheit.
- `tick()`-Methode: `this.nodeInfoCache.newTick(); this.topicInfoCache.newTick(); this._onDidChangeTreeData.fire(null);` — `startAutoRefresh` ruft `tick()` statt direkt zu feuern.
- `ensureNodeExpanded(item)`: 
  - `let info = this.nodeInfoCache.get(item.getNodeName())`;
  - falls `undefined`: `info = await this.getNodeInfo(item.getNodeName())` (bestehende private/public Methode mit System-Topic-Filter), `this.nodeInfoCache.set(name, info)`;
  - Item per neuem Setter `applyInfo(info)` aktualisieren (Description + gespeicherte Listen);
  - `this._onDidChangeTreeData.fire(item)` (pro Element).
- `ensureTopicExpanded(item)` analog mit `topicInfoCache`/`getTopicInfo`.
- Folder-`getChildren` (nodes): statt Info-Fetch → `items.push(new LiveNodeItem(name))`. (topics analog `new LiveTopicItem(name)`).

`live-items.ts`:
- `LiveNodeItem.applyInfo(info: LiveNodeInfo): void` — setzt private Felder + `updateDisplay()`; `LiveTopicItem.applyInfo(info: TopicInfo): void` analog.
- `LiveNodeItem.getChildren()` bleibt wie heute (nutzt die Felder; nach `applyInfo` gefüllt). Wichtig: `NodeParametersItem`-Pfad unverändert lassen (1.3.2-Parameter-Cache).
- Items behalten `CollapsibleState.Collapsed`.

Loop-Schutz (Design-Kern): `ensureNodeExpanded` feuert pro Element; der Fire führt NICHT erneut zu `ensureNodeExpanded` — der Cache-Treffer im selben Tick verhindert Refetch. Der „refetch on next tick"-Test pinnt das Ende-zu-Ende.
